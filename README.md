# dsh-pavovideo-auto
dsh-pavo-auto · 插件介绍
一个给 DeepSeek Harness（DSH） 用的浏览器自动化插件，把「Pavo AI 文生视频站点」变成可以批量、按脚本投递的流水线。

解决什么问题
AI 视频站是聊天式交互：一次只能输入一句提示词、等几分钟出片、再手动发下一句。做 60 段纪录片分镜时，这意味着 60 次重复劳动 + 60 次手动下载 + 60 次抽帧。

这个插件把这一整套变成一条命令：

代码块


pavo_pipeline start
它会自己发、自己等、自己下载、自己接下一段。

四个核心能力
1. 持久登录，不碰密码 独立 Chromium 用户数据目录，首次手动登录一次，之后一直复用；账号密码从不落盘。

2. 参数强制校准 每次发送前读设置按钮文案，核对比例与时长（如 16:9 / 10s），对不上就不发——避免"手滑发出竖屏 4 秒"这种废片。

3. 首尾帧接续 把上一段的末帧作为下一段的首帧上传，形成真正连续的镜头链。实测「全景铁索桥 → 桥面推进 → 攀索背影 → 夺桥红旗」四段可以无缝衔接。

4. 全自动闭环 发送 → 等出片 → 下载 mp4 → ffmpeg 抽末帧 → 下一段，每段完成发一条提示，日历式断点续跑。

安全设计
机制	作用
每日上限	默认 30 条，防超支
最小间隔	默认 90 秒，降风控概率
连续失败停	2 次失败自动停，不盲目重试
操作卡片	聊天里「紧急终止 / 继续」按钮，点一下就停
下载去重	按 URL 新出现判断，修掉了"把上一段当下一段"的经典坑

配置
所有路径都不写死，通过 cordis.patch.yml 的 config 覆盖：

dataDir（默认 ~/.pavo-auto）、clipsDir、framesDir
promptFile 或 segmentsFile（结构化分镜，含 firstFrame 标记）
ffmpegPath、intervalMs、minGapMs、dailyLimit、headless、notify
它不擅长什么（如实写在 README 里）
站点内容审核会拦部分历史题材表述，被拦就停，不会自行改词；
地图类画面 AI 没有地理常识，要求"路线图"基本画不对，建议换山峦/光带/篝火；
输出尺寸会漂：首帧模式下可能是 1260×720，拼接前要统一；
界面下载带水印，必须走 CDN 直链（pavo_download）。
适合谁
做系列短片 / 分镜纪录片 / 广告批量，需要几十上百段镜头的人；
想把「提示词清单」变成「成片文件夹」的创作者；
需要保留可追溯记录（每段发送日志 + 成片 + 末帧）的工程化用法。
定位
它不是"AI 视频生成器"，而是一个把生成站点变成可编排流水线的胶水层：你负责分镜与提示词质量，它负责重复劳动、等待、下载、接链和刹车。
